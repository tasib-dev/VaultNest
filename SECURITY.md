# Security Policy

## Supported Versions

The following versions currently receive security updates.

| Version | Supported |
|---------|-----------|
| 1.0.0 | Yes |
| Earlier versions | No |

---

## Reporting a Vulnerability

The security of Vault Nest is taken seriously. If you discover a security vulnerability, please report it responsibly.

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, send a detailed report to:

**Email:** akt629201@gmail.com

Please include the following information:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- The potential impact.
- Proof of concept (if applicable).
- Any suggestions for a possible fix.

---

## Response Process

After receiving a security report, the following process will be followed:

1. Acknowledge receipt of the report.
2. Verify and investigate the reported vulnerability.
3. Develop and test an appropriate fix.
4. Release a security update if necessary.
5. Publicly disclose the vulnerability after the fix has been released.

Every effort will be made to respond as quickly as possible.

---

## Scope

Examples of security issues include, but are not limited to:

- Authentication or authorization bypass
- SQL Injection (SQLi)
- Cross-Site Scripting (XSS)
- Cross-Site Request Forgery (CSRF)
- File upload vulnerabilities
- Remote Code Execution (RCE)
- Sensitive data exposure
- Session management vulnerabilities
- Privilege escalation
- Directory traversal

---

## Supported Release

The current stable release is:

**Version:** **1.0.0**

Security updates will be provided for the latest stable version.

---

## Responsible Disclosure

Please allow reasonable time to investigate and resolve any reported vulnerability before publicly disclosing it.

Responsible disclosure helps protect all users of Vault Nest and contributes to a safer software ecosystem.

Thank you for helping improve the security of Vault Nest.
